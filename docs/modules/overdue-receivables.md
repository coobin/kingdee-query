# 发票账龄

## 模块定义

| 项目 | 内容 |
| --- | --- |
| 工具 ID | `overdue_receivables` |
| 查询类型 | `overdue_receivables`，不是单一标准表单查询 |
| 结果粒度 | 一个存在超期风险的销售子项目一行 |
| 默认账龄 | 超过 180 天 |
| 统计日 | 服务端按 `Asia/Shanghai` 业务时区计算当天 |
| 默认排序 | 未回款金额降序，其次未生成应收金额降序、超期天数降序 |

## 数据来源

| 来源用途 | 金蝶表单 | 关键字段 |
| --- | --- | --- |
| 超期发票候选和开票日期 | `IV_SALESIC` | `FBillNo`、`FINVOICEDATE`、`F_PARA_SaleSubProId.FNumber`、`F_PARA_SaleSubProId.FName`、`FCustomerID.FName`、`FALLAMOUNTFOR`、`FRedBlue` |
| 全量有效发票 | `IV_SALESIC` | 同上；仅针对候选销售子项目补读 |
| 应收明细 | `AR_RECEIVABLE` | `FBillNo`、`FEntityDetail_FENTRYID`、`FIVALLAMOUNTFOR`、`FRECEIVEAMOUNT`、`FNORECEIVEAMOUNT`、`F_PARA_SaleSubProId.*` |
| 发票—应收匹配 | `AR_BILLINGMATCHRECORD` | 来源/目标单据号、分录内码、单据类型、本次和累计开票核销金额 |
| 应收—收款/退款匹配 | `AR_MATCHRECORD` | 来源/目标单据号、单据类型、已收款核销金额、未收款核销金额 |
| 收款单 | `AR_RECEIVEBILL` | 销售子项目、收款日期、收款金额 |
| 退款单 | `AR_REFUNDBILL` | 销售子项目、退款日期、退款金额 |
| 收款条件 | `PARA_SaleSubProject` | `FBillNo`、`FName`、`FRecConditionStr` |

收款条件来源使用运行时可查询的 `PARA_SaleSubProject`。该来源当前配置 `filters: []`，按 `FBillNo` 做销售子项目批量筛选；不能替换为设计器中的扩展 UUID 或其他未验证表单标识。

## 查询参数

| 外部参数 | 金蝶/计算用途 | 规则 |
| --- | --- | --- |
| `minimumDays` | 计算开票日期截止日 | 整数 1–3650，默认 180；截止日 = 统计日 - 天数 |
| `customerName` | 发票候选 `FCustomerID.FName` | 包含匹配，可选 |
| `subprojectNumber` | 发票候选 `F_PARA_SaleSubProId.FNumber` | 包含匹配，可选；兼容参数 `projectNumber` |
| `limit` | 最终销售子项目结果行数 | 只限制返回，不限制后台按来源分页读取 |

候选发票固定要求：已审核 `FDocumentStatus='C'`、未作废 `FCancelStatus='A'`、发票金额不为 0，并且 `FINVOICEDATE < 统计日 - minimumDays`。应收、收款、退款来源按已审核、未作废条件读取；发票—应收和应收—收款/退款匹配记录则按关联单号、来源/目标单据类型筛选，不使用单据状态条件。

## 结果字段字典

| 返回字段 | 类型 | 计算/来源 | 业务含义 |
| --- | --- | --- | --- |
| 客户 | 文本 | 发票、应收等来源的 `FCustomerID.FName` 去重拼接 | 销售子项目关联客户 |
| 销售子项目编码 | 文本 | `F_PARA_SaleSubProId.FNumber` | 汇总主键，大小写按规范化键合并 |
| 销售子项目名称 | 文本 | `F_PARA_SaleSubProId.FName` / `FName` | 多来源名称去重拼接 |
| 开票日期 | 日期 | 超期候选发票 `FINVOICEDATE` 的最早日期 | 账龄起算日期 |
| 超期天数 | 整数 | 统计日 - 开票日期 | 以自然日计算 |
| 超期发票数 | 整数 | 超期候选发票号去重计数 | 仅计入截止日之前的候选发票 |
| 应收单数 | 整数 | 应收单号去重计数 | 关联到该销售子项目的有效应收单数 |
| 开票金额 | 金额 | 超期发票金额按红蓝字净额化后汇总 | 不含该子项目未超期发票 |
| 已收款金额 | 金额 | 超期发票金额 - 应收未收款金额 - 未生成应收金额 | 按发票—应收匹配结果分摊 |
| 收款未核销金额 | 金额 | 超期范围已收款 - 已核销到应收的收款 | 不等同于未回款 |
| 未生成应收金额 | 金额 | 超期发票净额中没有形成对应应收的部分 | 不能直接认定为已回款或应收未收款 |
| 应收未收款金额 | 金额 | 超期发票范围内已形成应收但仍未收取的部分 | 经过应收明细和收款匹配分摊 |
| 未回款金额 | 金额 | `max(开票金额 - 已收款金额, 0)` | 风险金额，等于应收未收款金额 + 未生成应收金额 |
| 回款状态 | 枚举文本 | 按上述金额判断 | 见下方状态表 |
| 收款条件 | 文本 | `PARA_SaleSubProject.FRecConditionStr` | 同一子项目多个条件去重拼接，未找到时为空 |

页面和 `columns` 的公开列按上表返回。聚合对象内部还会记录结算组织和销售部门，但它们当前不属于公开列，不应作为页面或导出的正式数据字段。

## 计算口径

1. 先从销售发票找出满足账龄条件的候选发票，取得候选销售子项目和最早超期发票日期。
2. 针对候选子项目补读全部有效发票，但最终公开金额仍限定在超期发票范围；未超期发票不能改变账龄日期或金额。
3. 红字发票按负数参与净额化。红字冲销旧蓝字发票时，在销售子项目层面净额化发票与发票—应收匹配，避免把旧蓝字金额重复计入未生成应收。
4. 通过发票—应收匹配记录把应收未收款分摊回超期发票；没有应收匹配的部分进入未生成应收金额。
5. 收款单和退款单会被读取用于关联核对；严格匹配口径以 `AR_MATCHRECORD` 的来源/目标单据关系和未收款核销金额为准，不把该子项目全部收款单金额直接当作超期发票已收款。
6. 应收未收款金额和未生成应收金额都为零的子项目不会进入最终风险结果；缺少销售子项目编码或没有有效开票日期的明细会被排除，并在 `statistics` 中提示。

核心关系为：

```text
已收款金额 = 开票金额 - 应收未收款金额 - 未生成应收金额
未回款金额 = max(开票金额 - 已收款金额, 0)
未回款金额 = 应收未收款金额 + 未生成应收金额
```

## 回款状态

| 状态 | 判定 |
| --- | --- |
| 完全未回款 | 没有已收款或已核销金额，且存在应收未收款 |
| 部分回款未结清 | 已有收款或核销金额，但仍有应收未收款 |
| 未完全形成应收 | 超期发票只有部分形成应收，仍存在未生成应收金额 |
| 完全未形成应收 | 超期发票全部没有形成对应应收 |

已结清且没有未生成应收金额的子项目会在风险过滤阶段被排除，因此通常不会作为最终结果行返回。

## 统计信息与限制

`statistics` 至少包含统计日、账龄天数、销售子项目数、超期发票数、应收单数、客户数、未回款金额、应收未收款金额、已收款金额、收款未核销金额、未生成应收金额，以及完全未回款、部分回款、未完全形成应收、完全未形成应收的数量和金额。`missingInvoiceDateSubprojects`、`rowsWithoutSubproject` 用于说明被排除的数据。

模块会分页读取候选发票，并按销售子项目批量读取发票、应收、匹配记录、收款、退款和收款条件；后台扫描上限由分页和金蝶接口返回决定，页面行数只限制最终返回。该模块用于风险筛选，不替代财务对收款单、退款单、应收单和核销记录的最终对账。
