# 销售子项目经营分析

## 用途

`sales_business_analysis` 以 `PARA_SaleSubProject`（销售子项目）为主表，读取一个不超过 366 天的业务日期区间，并把订单、出库、销售发票、应收、收款和退款按销售子项目归集。页面中的主表用于经营排行，点击销售子项目编码可读取该子项目的跨单据明细。

这是只读分析模块，不会回写金蝶单据；模块默认是受限模块，只有超级管理员或模块人员名单中的金蝶用户名可以访问。

## 预计毛利率口径

- 明细行的 `预计毛利率` 直接来自销售子项目单据字段 `FGrossProfitRate`，金蝶显示名称为“预计毛利率(不含税)(%)”。
- `预计毛利` 来自 `FGrossProfitAmt`；合同金额和合同不含税金额分别来自 `FContractAmt`、`FContractNoTaxAmt`。
- 汇总卡片的“加权预计毛利率”按 `预计毛利 ÷ 合同不含税金额 × 100` 计算。不同子项目的百分比不会相加；合同不含税金额为零时显示为空。
- 若预计毛利率字段为空但预计毛利和合同不含税金额可用，服务端会给出推导值，并在行级数据状态中保留来源提示；不会把推导值伪装成金蝶原始字段。

## 数据链路和粒度

| 阶段 | 金蝶对象 | 关联键 / 日期 | 主要指标 |
| --- | --- | --- | --- |
| 主数据 | `PARA_SaleSubProject` | `FBillNo` / `FBizDate` | 客户、销售项目、项目状态、合同金额、预计毛利率、收款条件 |
| 合同 | `PARA_SaleContract` | `FSaleSuProjectId.FNumber` / `FBizDate` | 合同数、合同金额、预计毛利 |
| 订单 | `SAL_SaleOrder` | `F_PARA_SaleSubProId.FNumber` / `FDate` | 订单金额、订单数量、累计出库、退货、剩余出库、计划交货 |
| 交付 | `SAL_OUTSTOCK` | `F_PARA_SaleSubProId.FNumber` / `FDate` | 出库数量、实发数量、签收数量、出库金额 |
| 开票 | `IV_SALESIC` | `F_PARA_SaleSubProId.FNumber` / `FINVOICEDATE` | 销售发票数、开票金额、红蓝字净额 |
| 应收 | `AR_RECEIVABLE` | `F_PARA_SaleSubProId.FNumber` / `FDate` | 应收金额、应收已收款、应收未收款 |
| 回款 | `AR_RECEIVEBILL`、`AR_REFUNDBILL` | `F_PARA_SaleSubProId.FNumber` / `FDATE` | 收款金额、退款金额、收款净额 |

订单头金额按“销售订单号 + 销售子项目编码”去重，订单明细数量和交付字段按明细行相加。红字发票会以负数冲减蓝字发票；应收余额保留金蝶返回的正负号，页面另列“应收未收款”正数风险金额，避免把红字冲销误报成风险。

## 外部参数

- `dateFrom`、`dateTo`：必填日期（`YYYY-MM-DD`），结束日期包含当天，最多 366 天；未通过页面调用时服务端默认本年度截至今天。
- `customerName`：客户名称包含匹配。
- `projectNumber`：销售项目编码包含匹配。
- `subprojectNumber`：销售子项目编码包含匹配。
- `billNumber`：销售订单编号精确匹配。
- `salespersonName`、`organizationName`：在销售订单和销售出库来源上包含匹配，服务端只保留确实匹配到相关单据的销售子项目。
- `limit`：主表返回行数，受 `KINGDEE_MAX_ROWS` 限制；跨来源读取仍然完整分页。

## 数据状态和限制

每个来源都在 `sourceStatus` 中返回可用性和读取行数。销售子项目主来源不可用时查询失败；合同、订单、交付或财务来源不可用时仍返回可用部分，但 `partial=true`，行级“数据完整性”会标记缺少的来源。没有销售子项目编码的下游明细不会被猜测归属，并计入 `rowsWithoutSubproject`。

“收款净额”是收款单金额减退款单金额；“应收已收款金额”来自应收单自身字段，二者可能因核销期间和单据日期不同而存在差异，页面同时展示，不强行覆盖。该模块不把预计毛利率当作实际毛利率，也不从采购或成本单据推导实际毛利。

## 权限和核验

服务端只从目录登记的表单和字段读取数据，所有跨单据查询都由当前登录金蝶用户执行，并受金蝶业务权限、组织权限和数据范围约束。上线前应在目标账套的 BOS/WebAPI 测试页面核对以上对象和字段；如果二开账套字段不同，应先更新目录、测试和本说明，再部署。
