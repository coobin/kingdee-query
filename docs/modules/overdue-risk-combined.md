# 超期风险

## 模块定义

| 项目 | 内容 |
| --- | --- |
| 工具 ID | `overdue_risk_combined` |
| 结果粒度 | 一个存在发票或应收超期风险的销售子项目一行 |
| 默认发票账龄 | 超过 180 天 |
| 默认应收账龄 | 超过 270 天 |
| 默认排序 | 最终超期风险金额降序，其次超期天数降序 |

## 计算口径

模块先分别计算两个独立金额，再在销售子项目层面比较，不把两个金额相加：

```text
A = 发票日期超过 invoiceDays 的未回款金额
B = 应收单日期超过 receivableDays 的应收未收款金额
最终超期风险金额 = max(A, B)
```

如果 A 大于 B，采用发票口径，账龄日期取最早超期发票日期；否则采用应收口径，账龄日期取最早超期应收单日期。A、B 相等时采用应收口径。两个天数可以独立输入，默认分别为 180 和 270。

发票口径沿用 `overdue_receivables` 的严格金额核对逻辑；应收口径沿用 `receivable_aging` 的应收明细逻辑。两个视图仍然独立保留，风险模块只是提供项目级风险选口径和对比结果。

## 查询参数

| 外部参数 | 规则 |
| --- | --- |
| `invoiceDays` | 发票超期天数，整数 1–3650，默认 180 |
| `receivableDays` | 应收单超期天数，整数 1–3650，默认 270 |
| `customerName` | 客户名称包含匹配，可选 |
| `subprojectNumber` | 销售子项目编码包含匹配，可选；兼容 `projectNumber` |
| `limit` | 保留兼容，不截断合并结果；两个来源会先完整读取、汇总并比较 |

## 结果字段

| 返回字段 | 含义 |
| --- | --- |
| 开票未回款金额 | A，发票超期口径金额 |
| 应收未收款金额 | B，应收超期口径金额 |
| 金额差异 | A - B，正数表示发票口径更高 |
| 最终超期风险金额 | A、B 两者取高 |
| 采用口径 | `发票超期` 或 `应收超期` |
| 账龄日期 | 采用口径下的最早超期日期 |
| 超期天数 | 采用口径下的账龄天数 |
| 超期阈值 | 实际采用的 180/270 或自定义天数 |
| 应收未开票金额 | 应收口径范围内未匹配销售发票的金额 |
| 未生成应收金额 | 发票口径范围内尚未形成应收的金额 |

## 使用建议

该模块用于统一风险排序，不用于把发票和应收金额相加。风险模块会完整读取两个口径的分页结果，页面返回全部结果，不再沿用普通模块的 200 行返回上限。数据量较大时查询时间会增加。需要查看原因时，回到“发票账龄”和“应收账龄”两个明细视图核对发票—应收匹配、应收—收款核销和未开票应收。
