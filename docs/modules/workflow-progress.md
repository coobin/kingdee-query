# 审批进度

## 模块定义

| 项目 | 内容 |
| --- | --- |
| 工具 ID | `workflow_progress` |
| 金蝶表单 | 不使用标准 `ExecuteBillQuery`；调用部署配置的自定义只读 WebAPI |
| 数据粒度 | 指定单据的流程对象，通常包含当前节点和历史节点 |
| 启用条件 | 配置 `KINGDEE_WORKFLOW_METHOD` |
| 页面入口 | 当前网页没有固定审批进度表单，模块在目录中显示为待配置或可用 |

## 请求数据字典

| 外部参数 | 传给自定义接口的字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| `formId` | `FormId` | 文本 | 业务单据类型标识；必须与部署侧自定义接口支持的类型一致 |
| `billNumber` | `Number` | 文本 | 要查询的业务单据编号 |

服务端要求 `formId` 和 `billNumber` 同时非空，然后只调用环境配置中的方法名，并把 `{FormId, Number}` 作为 JSON 参数传入。调用方不能提交自定义 WebAPI 方法名、SQL 或任意额外参数。

## 输出数据

响应包含：

- `query.formId`、`query.billNumber`：本次查询条件；
- `workflow`：自定义审批进度接口原样返回的结构化对象；
- `summary`：仅说明已取得该单据的审批进度。

不同账套或二开接口的节点、处理人、审批意见、时间等字段可能不同，因此本模块没有固定字段表，不把未知字段解释为统一业务状态。

## 权限、启用状态和限制

- 未配置 `KINGDEE_WORKFLOW_METHOD` 时，目录仍可展示该模块，但 `available=false`，实际查询会失败并提示尚未配置。
- 当前用户必须同时具备 Query Hub 模块权限、金蝶登录权限和部署侧自定义接口允许的业务权限。
- 这是只读查询，不会提交、撤回、转交、催办或修改审批流程。
- 上游接口返回结构及其完整性由部署侧自定义 WebAPI 负责；本模块不补齐缺失节点，也不把接口返回为空解释为“没有审批流程”。
