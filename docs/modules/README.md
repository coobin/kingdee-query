# 查询模块数据说明

本目录是 Query Hub 当前查询模块的数据字典和口径说明。每份文档都以当前代码和 `config/query-catalog.json` 为准，记录模块标识、金蝶数据来源、返回字段、筛选语义、数据粒度、权限边界和已知限制。不记录真实账号、密码、密钥、域名、IP、客户名称、项目编号、金额或业务单据内容。

## 如何阅读字段

- “外部参数”是页面、Dify 或结构化 API 可以提交的参数名；“金蝶字段”是服务端目录中的 `FieldKeys` 或筛选字段。
- 普通模块的 `rows` 按对应文档的数据粒度返回，`columns` 是页面和导出的公开列。审批进度返回本人发起流程的当前节点和处理人列。
- 普通模块的编码、单据号和组织编码采用精确匹配；名称字段采用包含匹配；`dateFrom` 包含当天，`dateTo` 通过“结束日期的下一天”实现闭区间效果。
- 页面当前按请求发送 `limit=100`；普通模块服务端默认值为 50，并受 `KINGDEE_MAX_ROWS` 限制（默认 200，代码上限 1000）。发票账龄会按数据来源分页读取；超期风险会完整读取两个口径并返回全部结果，不能把普通模块的返回上限套用到该模块。
- 费用金额求和使用 `aggregation=sum_amount`，按当前查询实际读取的单据头金额汇总；达到 `KINGDEE_AGGREGATION_MAX_ROWS` 时会标记为可能不完整。

## 统一权限和安全边界

- 页面使用结构化条件；普通标准查询不接受任意 SQL、金蝶过滤表达式、任意 `FormId`、返回字段或 WebAPI 方法作为用户输入。审批进度的 `formId` 只作为已配置只读接口的业务参数，发起人始终来自当前登录上下文。
- 服务端再次检查模块、字段、筛选范围和返回行数；填写条件不会扩大金蝶权限。
- 查询使用当前登录身份访问金蝶，最终结果仍受金蝶业务权限、组织权限和数据范围约束。
- 模块访问名单只负责进一步收紧 Query Hub 入口，不能授予金蝶原本没有的业务权限。
- 人员成本包含工资隐私，默认仅超级管理员可见；管理员必须在模块名单中明确加入金蝶用户名，普通 SSO 用户才会看到入口。
- 查询结果会记录审计信息，但文档、测试数据和示例不得包含真实业务数据。
- 修改模块字段或金额口径时，必须同步更新 `config/query-catalog.json`、对应查询逻辑、测试和本目录文档。

## 敏感信息检查

提交前请确认文档没有出现：

- 账号、密码、Passkey、API Key、应用密钥或代理共享密钥；
- 生产域名、内网地址、服务器地址、数据库连接信息；
- 真实客户、员工、销售子项目、合同、单据编号或金额；
- 从金蝶导出的原始行、权限清单、审计日志或业务附件。
