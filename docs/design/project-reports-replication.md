# 金蝶三张项目报表复刻方案

2026-11-24 · 设计评审稿

## 交付目标与依据

员工从 Query Hub 查询与金蝶原表同口径的数据。首期以复用原报表服务为主，让金蝶继续负责单据关联、计算、舍入和小计，Query Hub 负责查询条件、授权和展示。先验证结果一致，再验证公司角色配合只读账号的访问模式。减少许可的实际效果取决于公司合同的计量方式。

| 报表 | 本次核对依据 | 开发起点 |
| --- | --- | --- |
| 项目购销一致性报表 | 本仓库目录、查询引擎、页面和[现有字段字典](../modules/project-pur-sale-consistency.md) | 已有模块，补齐对账与权限验收 |
| 项目现金流量表 | 内部《项目现金流量表取数逻辑》“金蝶项目现金流量表”页、《现金流量表取数逻辑梳理 20250226》、《预算项目新增沟通0425》票据规则 | 已有29个业务列及取数说明，需确认生产版本、报表标识和行粒度 |
| 项目预算执行情况表 | 《预算项目新增沟通0425》“当前沟通情况0425（沟通后确认）”“当前沟通情况0528”等工作表 | 已有科目及执行来源线索，需取得原表列头、期间、预算版本和实际结果 |

内部材料同时包括历史需求和沟通稿。以下涉及现金流、预算的公式用于设计对账用例，其生产有效性以同一账套的原表为准。尤其要按菜单和标识区分“项目执行情况表”和“项目预算执行情况表”。

## 1. 项目购销一致性报表

现有工具 project_pur_sale_consistency 调用 GetSysReportData，报表 PARA_PM_ProjectPurSaleRpt 配套过滤器 PARA_ProjectPurSaleRptFilter。50个固定列按原顺序映射。项目、子项目是业务锚点，同一子项目随合同、应收应付、实收实付、票据和发票展开多行。保留行类型、空值、原始正负号和期初列。不能按合同号去重或把重复展示的合同金额逐行求和。

已接入组织、项目、子项目、销售部门、客户和签订日期范围。行业列可展示，行业过滤器的序列化仍待验证。当前接口从第0行读取，返回上限和原表总行数分开。核对一份多合同、多单据的子项目，比较行集合（含重复次数）、列序、金额和分页边界；行业筛选和完整导出单独验收。

## 2. 项目现金流量表

资料列出公司主体、项目归属、客户、客户经理、行业、项目类型、项目与子项目编码及名称、销售合同号/金额/签订日期，随后为16个金额与比例列。筛选画面含部门、客户、行业、客户经理、项目、子项目、合同签订时间和业务日期。用一子项目多合同样本确认现金流归属层级及合同间分摊，同时分别移动两类日期边界。

| 指标组 | 历史取数说明及原表核对重点 |
| --- | --- |
| 现金收款 | 期初已收、收款单、满足状态的票据及收款退款。0425沟通页将银承、商承在收款时计入，支票待到期收款、贴现或背书；早期资料采用不同状态条件。用同一票据跨期验证确认时点。 |
| 现金付款及采购付款 | 追溯期初、设备/服务采购付款、项目分摊、返点、专项付款及报销发生和调整。采购付款汇总另有独立口径。付款退款、银承开具时50%及到期补足、背书付款逐笔核对。 |
| 合同、费用和交付 | 采购合同金额含设备/服务外采、期初和调整；专项费用分采购金额、采购付款和报销；内部服务按小单元服务收入确认、期初及调整；人员交付还涉及月度成本、报销和非专项费用物料采购付款。相邻指标可能覆盖同一单据。 |
| 开票未收款、开票未付款 | 历史字段说明分别指向应收票据状态为空或背书退回、应付票据状态为空。需核对这里“开票”的业务含义，并检查原票拆分后是否同时计入母票和子票。 |
| 现金流（收付款维度） | 资料公式为现金收款 + 开票未收款 − 现金付款 − 开票未付款。 |
| 现金流（票据维度） | 资料公式为现金收款 − 现金付款。保留原表列名，通过有未结票据的项目同时验证两列。 |
| 合同已回款比例、已付款比例 | 分别为现金收款 / 销售合同金额、采购付款汇总 / 采购合同金额。核对零分母、跨合同汇总和显示精度。 |

## 3. 项目预算执行情况表

先建立“预算取自哪版、实际发生在哪个环节、按什么期间归集”的逐列字典。立项、立项变更、子项目预算调整和项目预算成本调整都在资料的影响范围。用同一子项目调整前后两期对照，确定原表展示原始预算、调整额、有效预算中的哪些列，调整按什么日期生效。以原表确认科目横排或纵排、项目层级、含税/未税、执行余额或执行率的定义。

| 科目 | 沟通资料列出的执行来源或公式 |
| --- | --- |
| 销售收入、设备外采、服务外采 | 销售合同及合同税率明细、对应采购合同。覆盖一个合同多个税率的样本。 |
| 内部结算、人员交付、专项费用 | 小单元服务收入确认单、成本型员工相关支出、专项采购合同及报销。用已签未付合同区分合同执行和现金付款。 |
| 税务成本 | 0425页区分按实际收开发票计算的附加税和按未税合同额计算的印花税；0528页的计算基数存在差异。按生产结果核对取数依据及舍入顺序。 |
| 资金成本 | 资料描述负现金流期间按日计息、年基数365；0425页另列汇票贴现成本，基数360。确认负值呈现、计息起止日、利率来源、历史修正和贴现成本是否生效。 |
| 毛利及派生比例 | 0425页预计未税毛利等于未税销售收入减各项未税成本，毛利率用未税收入作分母。另有贡献毛利类指标，是否展示及预算与实际列的差别须核对原报表。 |

## 4. 技术实现

1. **取得接口契约。** 在授权账套分别打开两张新增原表，记录报表和过滤器 FormId、过滤方案、模型默认值、字段键顺序、基础资料序列化、期间和返回行类型。以单项目最小请求回放 GetSysReportData，再改变一个筛选条件验证确实生效。留存脱敏契约和样例；记录账套版本、筛选条件、生成时间和角色，便于再现。
2. **接入查询引擎。** 在 config/query-catalog.json 登记固定字段和筛选白名单，复用 src/kingdee.js 的报表客户端及基础资料解析。src/query-engine.js 当前专用逻辑写有合同日期键、工具 ID、StartRow=0，按各报表契约配置日期键和工具标识。若原服务支持稳定翻页，传入有边界的偏移和限制并校验总数；发生截断、缺列或分页漂移时明确提示，避免导出不完整结果。小计、总计和比率取原表值。
3. **按报告能力选择替代路径。** 若 WebAPI 缺字段或不支持原过滤器，优先核实已部署报表插件可提供的只读查询服务。若必须由单据重建，再取得生产插件或业务确认的逐列规则，明确组织、关联键、期初、调整、冲销、符号和汇总层级；通过同一套基准样本后启用。
4. **执行授权。** 第一轮用同一金蝶身份与原表对账。服务账号试点时分开记录员工身份与执行身份，按公司角色授予报表、组织或项目范围、字段及导出动作。后端将请求与授权取交集，再交金蝶计算；如果接口无法在计算前表达该范围，停用该报表的服务账号模式。组织选择器、基础资料搜索、总行数、合计、导出及后续 MCP/AI 结果都受同一范围约束。授权缺失默认拒绝。
5. **页面与审计。** 沿用现有报表页面和服务端入口，按原表顺序展示字段、筛选、层级及合计。记录员工、报表、有效范围、执行模式、行数、截断状态和请求编号。不同权限的用户分别验收。采购和销售金额等受限字段涉及的派生指标须随字段一并授权。

## 5. 实施顺序与验收条件

| 阶段 | 交付与通过条件 |
| --- | --- |
| 原表取样 | 每表留一组原表导出及对应筛选，覆盖正常项目和关键边界。记录原表版本、权限和业务数据截止时点，整理字段映射及待决差异。 |
| 购销一致性基线 | 已有入口与原表比对多合同、跨页、空字段、红字和期初；确认本轮覆盖的筛选及任何缺口。 |
| 现金流量表 | 核对电汇、退款、未结及到期票据、拆票、跨期和含期初的合同。两种现金流、合同回款/付款比例及小计逐列对账。 |
| 预算执行情况表 | 核对预算调整前后、多税率合同、已签未付、零收入和负现金流项目。用同一个项目关联检查资金成本取用的现金流维度。 |
| 授权试点与发布 | 比较同条件下授权员工、异组织员工、撤权员工的查询与导出；验证跨项目合计和总行数。按报表逐个启用，异常时关闭相应新入口或切回已经验收的员工身份模式。 |

同条件、同数据时点下，行数、行类型、业务键及重复次数一致，金额和比例按原报表展示精度逐列一致；空值、零值、负数、汇总行及分母为零的显示一致。每项差异附原列、样例、差值和定位结果，涉及金额或可见范围的未解释差异阻止该表上线。

两张新表以员工金蝶身份读取，默认限制模块名单。后台可按模块分配访问，MCP 接入中心另行审核开通。Web、结构化 API 和 MCP 共用同一报表服务。默认组织编码 100，按当前员工可查看的子项目查得组织内码，传给原表 FOrgList。支持单组织、项目、子项目、部门、客户、合同日期和业务日期。现金流历史期间、行业及客户经理快捷条件未接入。金额、百分比和空单元格保留金蝶返回的展示值。生产单项目样本已分别对齐原表全部 32 列和 52 列，尚未逐类覆盖所有退票、预算变更及跨期业务样本。

三张表支持按页读取和导出当前页。现金流宽范围查询可能超过服务超时，按子项目检索已验证。购销一致性报表在指定子项目后仍可带回大量销售子项目编码为空的原始行，页面标明本页数量，不能用报表总行数推断该子项目的单据数。行数据及员工映射保留在业务系统内。
